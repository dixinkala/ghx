# GitHub 加速器 · 安卓版

原生 APK，37 KB，装上即用：不需要 root、不需要 Python、不依赖 proot 或任何后台服务。

安装包：[Releases](https://github.com/dixinkala/ghx/releases) 直接下载 `ghx.apk`（最新 v2.15，45 KB）。

产物：`android/ghx.apk`（包名 `com.ghx.accel`，minSdk 29 / targetSdk 34，当前版本 2.14）

## 四个功能

| 功能 | 说明 |
|---|---|
| 加速下载 | 多镜像轮询 + 6 分片并行，文件存到「下载/ghx」 |
| 只读浏览 | 把 README / 源码抓成文字页渲染，省流量、打不开网页时能看内容 |
| 优选 IP | 对候选节点做真实 TLS 握手 + 证书域名校验，挑当前网络最快的 |
| DNS 加速 | 本地 VPN 只接管 `github.com` / `api` / `codeload` 的 DNS，返回优选 IP；其他流量不进隧道 |

## 安装

1. 把 `ghx.apk` 传到手机（微信/QQ/数据线都行），点开安装，允许「未知来源」。
2. 想用 DNS 加速时，打开应用里的开关，系统会弹 VPN 授权，点确定。
3. 手机如果开了「私人 DNS」，改成「自动」，否则 DNS 查询走 DoT，会绕过本应用。

验证 DNS 是否生效：状态卡会显示 `DNS: github.com → x.x.x.x`，这个 IP 应与「优选 IP」里的一致。

## 2.1–2.4 修了什么（重要）

2.0 的 DNS 加速会把**所有** DNS 应答写坏：UDP 校验和的伪首部漏了协议号和长度，
还把补码后的值当成累加初值，导致系统把每个应答都判为坏包丢弃。
表现就是：开了开关既没有加速，其他网站也解析失败。

2.1–2.4 的改动：

- 按 RFC 768 重写伪首部与校验和，单测直接对照独立实现算出的固定值（0x8fea / 0xa541）。
- 私人 DNS 为「指定主机名」时直接拒绝开启，并提示怎么改。
- 开启后 3 秒自动解析一次，失败立刻关闭 VPN 并提示——不会再把手机留在断网状态。
- 没做过「优选 IP」就不接管任何域名，全部按系统原有方式解析。
- 2.3：只读浏览改成并发抢答（原来 5 个候选 × 6 个镜像串行重试，真机上能卡 2 分钟）。
- 2.3：离开再回到应用时恢复按钮状态，修掉"永远转圈"；回调加空 WebView 保护。
- 2.4：镜像测速结果缓存 30 分钟，下载前不再固定等一轮测速。
- 2.5：只读浏览支持 `owner/repo` 简写（真机上发现简写会被当成普通网址，报"抓不到内容"）。
- 2.6/2.7：断点续传。旧版临时文件名带时间戳，进程被杀后必然从头下；现在固定文件名，
  分片各自写成 `.cN` 文件，重来只补缺的片；片内也能从已有长度继续追加；
  单流续传改用闭区间 Range（部分镜像对 `bytes=N-` 会回 200 全量）；临时文件放在 files 目录，避免被系统当缓存清掉。
- 2.16：直连可达性探测——开 DNS 前先验 IP，整网不通直接提示并保持关闭；优选全部失败时明确报错；开着时每 5 分钟自检，IP 失效自动切换。
- 2.14：DNS 开关优化——没优选过自动先优选、连接中状态、失败回弹并给原因；解析行关闭时清空、开着时每 5 秒自动刷新，缓存未过期会标「系统缓存，稍后生效」。
- 2.12：浅色主题（右上角切换，默认跟随系统并记住选择）、开关对比度、空状态；图标定为深蓝闪电。
- 2.11：重做界面（品牌栏、状态卡、镜像速度条、44px 触控高度）与自适应图标（深蓝渐变 + 闪电 + 速度线，含 Android 13 主题图标）。
- 2.9：下载加「暂停 / 继续」按钮；暂停保留分片，继续接着下（比杀进程验证可靠得多）。
- 2.8：真机上冷启动测速会卡死（`Future.get()` 无超时，单个镜像 DNS 卡住就永远不返回）。
  改成总预算 25 秒、单次探测 8 秒超时；测速缓存从 30 分钟延长到 12 小时。

## 已知限制

- **没有 root 就改不了系统 hosts**。浏览器加速只能做到 DNS 层（换更快 IP），
  像 `raw.githubusercontent.com` 这种 SNI 阻断的域名，DNS 换了也没用，得用应用内下载/浏览走镜像。
- 镜像都是第三方公开反代：只下公开内容，别传私有仓库或 token。
- 推送代码用官方地址（`git push github 分支`），镜像只适合拉取。
- APK 用自签名证书（`android/keystore/ghx.jks`，口令 `ghxandroid`）。
  以后升级必须用同一个 key，否则要先卸载旧版。
- targetSdk 34 但没有申请通知权限，所以 VPN 状态条只有系统的那个图标。

## 自己重新构建（在手机上）

```bash
cd android
./setup-sdk.sh     # 首次：下载 android.jar 与 build-tools
./build.sh         # 产出 ghx.apk 并自动签名校验
```

构建链全部在手机 aarch64 上跑：`aapt`（原生 arm64 包）→ `javac`（OpenJDK 17）
→ `d8`（纯 Java）→ `zipalign`（原生）→ `apksigner`（纯 Java）。
不用 Gradle，不联网拉依赖（只有首次 setup 下 SDK 两个 zip）。

## 代码结构

```
android/
├── AndroidManifest.xml        权限、Activity、VpnService 声明
├── assets/index.html          界面（WebView 里的单页）
├── src/com/ghx/accel/
│   ├── MainActivity.java      WebView 宿主 + VPN 授权
│   ├── Bridge.java            JS ↔ 原生桥（下载/浏览/测速/开关）
│   ├── DnsVpn.java            只接管 DNS 的 VpnService
│   ├── DnsConfig.java         域名 → IP 映射持久化
│   └── core/                  纯 Java，可脱离 Android 单测
│       ├── DnsPacket.java     DNS 报文与 IPv4/UDP 封装
│       ├── Mirrors.java       镜像测速与 URL 拼接
│       ├── Downloader.java    分片下载、镜像回退、续传
│       ├── IpPicker.java      TLS + 证书校验的 IP 探测
│       └── Http.java          极简 HTTP 客户端
└── test/DnsTest.java          JVM 单测（DNS 报文/校验和）
```

## 测试

```bash
cd android
./test.sh          # 全部：纯逻辑 + 真实网络 + APK 检查（约 1 分钟）
./test.sh --fast   # 跳过联网部分
```

| 测试 | 覆盖内容 | 联网 |
|---|---|---|
| `DnsTest` | 报文解析、应答构造、IP/UDP 校验和（对照独立实现的 0x8fea / 0xa541） | 否 |
| `PacketTest` | Android 风格 EDNS 查询 → 应答 → 封包，产出 88 字节报文供外部逐字段校验 | 否 |
| `RouterTest` | 命中映射立即应答、未命中转发真实上游、非 DNS 包放行 | 是（转发用） |
| `CoreTest` | 镜像测速、1.29 MB 分片下载、候选 IP 的 TLS + 证书校验 | 是 |
| APK 检查 | 签名、清单版本、dex 里是否含 DnsRouter/自检逻辑 | 否 |

`PacketTest` 生成的报文用一个独立的 Python 实现（RFC 1071 / RFC 768）再校验一遍：
IP 校验、UDP 伪首部校验、DNS id、问题域名、应答地址共 13 项，全部通过。

2.1 之前的 DNS 故障就是被这组对照测出来的（旧代码 UDP 校验和 0xd695，正确值 0xa541）。

## 仍需真机验证

VpnService 的 tun 读写、Android 的 DNS 路由、以及系统 VPN 授权弹窗依赖真机行为，本地无法模拟。
应用里已加 3 秒自检：开启后解析失败会自动关闭并提示。

- 2.2 及更早：只读浏览输入 `owner/repo` 简写会失败，2.5 已修。
